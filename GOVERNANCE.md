# Governance

Vibewaiting is maintainer-led and developed in the open.

## Decisions

Substantial changes begin with a GitHub issue or discussion describing the user
problem, scope, trust-boundary impact, and alternatives. Maintainers seek rough
consensus, but retain final responsibility for product scope, security, releases, and
repository administration. Decisions should be attributable in an issue, pull request,
or architecture document rather than an unrecorded private channel.

## Roles

- **Contributors** participate through issues, discussions, reviews, documentation, or
  code.
- **Maintainers** triage, review, merge, release, handle security reports, and enforce
  the Code of Conduct. The initial maintainer is
  [@yueranyuan](https://github.com/yueranyuan).

Maintainer access may be offered after sustained, constructive contributions and sound
judgment around the browser/native security boundary. It may be removed for inactivity,
security risk, or Code of Conduct violations after a private discussion when practical.

## Scope

Vibewaiting is a thin browser and mobile companion for Supercode-backed coding-agent
sessions. It does not aim to become a coding harness, IDE, hosted execution service, or
general remote-desktop product. See [ROADMAP.md](ROADMAP.md).
